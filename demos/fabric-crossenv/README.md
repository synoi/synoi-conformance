# fabric-crossenv: minimal cross-environment, cross-implementation receipt chain

A MINIMAL PROOF, not a product. It shows two INDEPENDENT, non-gateway
runtimes emitting a SINGLE linked, offline-verifiable receipt chain across a
"game" action and a "work" action, under one operator identity. It proves
two axes at once:

- **environment-crossing**: R1 is a game action, R2 is a work action, R2
  carries `prev = R1.oid` INSIDE its signed canonical payload, so the two
  receipts form one tamper-evident chain, not two unrelated objects.
- **implementation independence**: R1 and R2 are signed by two different
  keypairs, generated by two separate scripts that do not import each
  other's signing code and do not import any gateway code. Both use only
  the open `@synoi/sraid` library (canonicalize, `cdroContentCore`, `pae`,
  OID computation) plus `@noble/curves` (Ed25519) and `@noble/post-quantum`
  (ML-DSA-65), the same open primitives a genuinely third-party emitter
  would use.

## What is proven

Run `verify-chain.ts` (see Reproduce below) with **no SynOI gateway process
running**. It:

1. Loads R1 (`out/r1.json`, signed by `runtime-a-game`) and R2
   (`out/r2.json`, signed by `runtime-b-work`).
2. Assembles them into a `synoi-evidence-bundle-v2` and calls
   `@synoi/verify-core`'s **shipped** `verifyEvidenceBundle` (not a
   reimplementation) — the same function the gateway's own self-verify and
   the `@synoi/verify` CLI both call.
3. Asserts BOTH Ed25519 AND ML-DSA-65 verify for EACH receipt
   (AND-enforced), under each receipt's OWN signer key (two different
   `verifying_key_id` values).
4. Asserts `R2.prev === R1.oid`.
5. Asserts the receipts carry `environment: 'game'` / `environment: 'work'`
   respectively.
6. Runs a TAMPER test: flips one byte in R1's signed attestation payload and
   shows the bundle now fails (`content-digest-mismatch` +
   `receipt-signature-invalid`), and a second tamper test that edits a body
   field in R2 without re-signing and shows the payload-binding recompute
   catches it.

The last recorded run: `out/verify-transcript.txt` — **9 passed, 0 failed**.
`out/receipts.json` holds R1 + R2 with real computed OIDs and real hybrid
signatures (see below on key handling).

## What is NOT proven

- **Not court-admissible, not regulator-accepted.** The bundle's own
  `honesty` block says so explicitly; that is a legal determination this
  code cannot make.
- **Not identity-resolved.** `OID_op` is a real content-addressed OID
  (`sha256:` + hex(sha256(canonicalize(descriptor)))), computed with the
  same `oidOf()` the gateway uses, but it is NOT resolved through the SynOI
  OID Resolver against a real persona. It anchors "the same operator
  claims both actions," not "this operator is a verified real person."
- **Not language-diverse.** Both runtimes are TypeScript. The prompt that
  spawned this proof pointed at a Rust b1-harness
  (`synoi-gateway/runtime/b1-harness`) as a possible cross-language Runtime
  A. That harness lives inside the `synoi-gateway` working tree, and the
  task constraints explicitly forbid touching that working tree or running
  gateway builds. Building/running it would require `cargo build` inside
  the gateway repo, which risks writing build artifacts into a tree marked
  read-only for this task. So both runtimes here are independent
  TypeScript programs (no shared code beyond the open libraries), proving
  implementation independence at the code level, not at the
  language/toolchain level. See REPORT item 3 below for what closing that
  gap would take.
- **Test keys, not production keys.** Both runtimes generate fresh Ed25519
  + ML-DSA-65 keypairs in-process on every run (`out/*-keys.secret.json`,
  clearly labeled TEST KEYS ONLY). A real deployment would keep private key
  material in each runtime's own custody (HSM/KMS/Vault) and export only
  the public bundle, exactly as `synoi-gateway/scripts/gen-receipt-signing-bundle.mjs`
  documents for the gateway's own signer.
- **No HITL hop.** This proof is exactly R1 -> R2, no out-of-band approval
  gate between them. See REPORT item 4 for the estimate to add one.
- **No absence statements, no Merkle-DAG beyond a two-node chain, no
  resolver, no revocation.** This is the smallest possible proof of the two
  target axes, not a general evidence-export feature.

## Files

- `operator-identity.ts` — computes `OID_op` (writes `out/operator-identity.json`).
- `runtime-a-game/emit-game-receipt.ts` — Runtime A. Signs R1, a
  `game.in_app_purchase` decision receipt. Writes `out/r1.json` +
  `out/runtime-a-keys.pub.json` (+ `.secret.json`, test keys).
- `runtime-b-work/emit-work-receipt.ts` — Runtime B. Reads `out/r1.json`
  for `R1.oid` only (no shared signing code with Runtime A). Signs R2, a
  `calendar.write` decision receipt with `prev = R1.oid`. Writes
  `out/r2.json` + `out/runtime-b-keys.pub.json` (+ `.secret.json`).
- `verify-chain.ts` — the standalone offline verifier described above.
  Writes `out/receipts.json` (the combined evidence) and prints the
  transcript.
- `out/` — generated evidence from the last run (checked in for review;
  regenerate any time with the commands below).

## Reproduce

From this directory, with no SynOI gateway process running:

```
npx tsx operator-identity.ts
npx tsx runtime-a-game/emit-game-receipt.ts
npx tsx runtime-b-work/emit-work-receipt.ts
npx tsx verify-chain.ts
```

Or capture a fresh transcript:

```
npx tsx verify-chain.ts > out/verify-transcript.txt 2>&1
```

## Why no honest blocker was hit

Every field the signed canonical projection needs
(`cdroContentCore`/`canonicalize`/`oidOfCanonical`/`pae`) is public in
`@synoi/sraid`'s published surface (`synoi-sraid/src/index.ts`), and the
verifier (`@synoi/verify-core` `verifyEvidenceBundle`,
`synoi-verify-core/src/bundle.ts`) recomputes the SAME
`canonicalize(cdroContentCore(receipt))` projection to check the
attestation payload. A byte-exact round trip using ONLY
`@synoi/sraid` + `@noble/curves` + `@noble/post-quantum` (no gateway
imports) was confirmed directly before building the runtimes, and the
9/9 pass on the full chain confirms it end to end. Nothing here required
copying gateway-private code (e.g. `verify-router.ts`'s
`signCanonicalBytesHybrid` or the `SigningOracle` custody seam) — those
exist to manage KEY CUSTODY inside the gateway, not to define the signed
byte shape, which is fully public.
